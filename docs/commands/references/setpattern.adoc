== setpattern

Selects a pattern as the current painting color.

=== Syntax

----
pattern setpattern → –
comp1 … compn pattern setpattern → –
----

=== Stack Effects

Earlier operands remain unchanged. Stack level 0 is the top of the stack.

.Before
[cols="1,3"]
|===
| Level | Object

| n … 1 (if needed)
| `comp1 … compn` (uncolored pattern components)

| 0
| `pattern` (instance returned by makepattern)

|===

.After
[cols="1,3"]
|===
| Level | Object

| (none)
| Pattern selected as the current color

|===

=== Description

`setpattern` selects a Pattern color space and installs a pattern instance. Subsequent fills, strokes, and text painting use the pattern.

If the current space is not Pattern, it becomes the underlying space of the new Pattern space. An existing Pattern space is retained. Colored patterns take only the pattern operand; uncolored patterns also take components in the underlying space.

For an uncolored RGB tile, select `/DeviceRGB` first, then push red, green, blue, and the pattern. The tile's `PaintProc` must not set its own color.

=== PostScript Level

*Level 2* and later

=== Examples

.Painting an uncolored tile in red
[source,postscript]
----
gsave
  /DeviceRGB setcolorspace
  1 0 0
  << /PatternType 1 /PaintType 2 /TilingType 1
     /BBox [0 0 6 6] /XStep 6 /YStep 6
     /PaintProc { pop 0 0 3 3 rectfill }
  >> matrix makepattern
  setpattern
  20 20 90 40 rectfill
grestore
----

=== Error Conditions

Common errors include the following; procedures and device operations can raise additional errors.

[cols="1,3"]
|===
| Error | Condition

| `stackunderflow`
| The pattern or required color components are missing.

| `typecheck`
| The pattern or a color component has the wrong type.

| `rangecheck`
| An uncolored pattern has no underlying color space.

| `undefined`
| Color changes are forbidden in the current painting context.
|===
