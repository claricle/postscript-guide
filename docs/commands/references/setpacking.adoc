== setpacking

Controls whether the scanner creates packed procedure arrays.

=== Syntax

----
bool setpacking → –
----

=== Stack Effects

Earlier operands remain unchanged. Stack level 0 is the top of the stack.

.Before
[cols="1,3"]
|===
| Level | Object

| 0
| `bool` (`true` enables array packing)

|===

.After
[cols="1,3"]
|===
| Level | Object

| (none)
| Operand consumed; scanner packing mode changed

|===

=== Description

`setpacking` controls the representation of procedures subsequently read by the PostScript scanner. With `true`, procedures written using braces are created as packed arrays; with `false`, they are ordinary arrays.

Packed arrays save memory and support execution and reading, but their elements cannot be replaced with `put`. This setting does not repack existing procedures or change arrays created by `array` or square brackets.

The setting takes effect when text is scanned. A procedure containing `setpacking` has already been read before it executes, so use separate input tokens or a string with `cvx exec` when demonstrating the change. Restore the previous mode with `currentpacking`.

=== PostScript Level

*Level 2* and later

=== Examples

.Reading a packed procedure
[source,postscript]
----
currentpacking
true setpacking
({ 2 3 add }) cvx exec
dup type ==           % packedarraytype
exec ==               % 5
setpacking
----

.Reading an ordinary procedure
[source,postscript]
----
currentpacking
false setpacking
({ 2 3 add }) cvx exec
type ==               % arraytype
setpacking
----
