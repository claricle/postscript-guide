== currentglobal

Reports whether new composite objects are allocated in global VM.

=== Syntax

----
– currentglobal → bool
----

=== Stack Effects

Earlier operands remain unchanged. Stack level 0 is the top of the stack.

.Before
[cols="1,3"]
|===
| Level | Object

| (none)
| No operands required

|===

.After
[cols="1,3"]
|===
| Level | Object

| 0
| `bool` (current allocation mode)

|===

=== Description

`currentglobal` returns `true` when global allocation is selected and `false` when local allocation is selected.

The result describes the allocation mode, not the location of an existing object. Changing the mode does not move objects that have already been created.

Use the returned boolean with `setglobal` to restore the caller's allocation mode after creating temporary objects. The allocation mode is not a graphics state parameter, so `gsave` and `grestore` do not preserve it.

=== PostScript Level

*Level 2* and later

=== Examples

.Inspecting the allocation mode
[source,postscript]
----
currentglobal ==  % Prints true or false
% The query leaves the allocation mode unchanged.
----

.Temporarily allocating globally
[source,postscript]
----
currentglobal        % Keep the caller's mode on the stack
true setglobal
10 array             % Allocate an array in global VM
exch setglobal       % Restore the previous mode
pop                  % Discard the array reference
----

=== Error Conditions

Common errors include the following; procedures and device operations can raise additional errors.

[cols="1,3"]
|===
| Error | Condition

| `stackoverflow`
| There is no room on the operand stack for the boolean.
|===
